## 2.0.1 — 2026-08-28

**전문가용 메인보드 단추가 제 창을 다시 열던 것을 고친다.**

### 고친 것

단추를 누르면 메인보드가 아니라 특허 출원 안내 창이 새 탭에 하나 더 떴다. 거기서 한 번
더 눌러야 메인보드가 나왔다.

까닭이 둘 겹쳐 있었다.

1. `<a href="#" target="_blank">` 는 **지금 쪽을 새 탭에 여는 짓**이다. 주소가 잡히기
   전에는 `#` 인 채였다.
2. 주소가 없을 때 `hidden` 으로 감췄으나 먹지 아니하였다. `.btn` 에 준
   `display:inline-flex` 가 UA 의 `[hidden]{display:none}` 를 이긴다. 그래서 갈 곳이
   없는 단추가 보였다.

두 번째 탭에서는 그새 보드가 떠 있어 제대로 열렸다. 그것이 「두 번 눌러야 나온다」 의 정체다.

**고친 법.** 링크를 단추로 바꾸고 **누른 때에 주소를 받아 연다.** 미리 박아 두지 아니하니
죽은 주소가 생길 수 없다. 아직 뜨는 중이면 기다리고, 죽었으면 다시 띄운다. 주소만 들고
있다가 죽은 것을 내주지 아니하도록 붙어 보고 확인한다.

### 실측

- 그냥 누름 → 200
- 보드를 죽인 뒤 누름 → 3.1초 만에 되살려 200. 안내창과 다른 창인 것도 확인
- 자체 점검에 두 가지를 더함 — 빈 주소에 `target="_blank"` 가 걸렸는지,
  `[hidden]` 을 눌러 주는 규칙이 있는지. 일부러 되돌려 실제로 잡는 것을 확인

## 2.0.0 — 2026-08-28

**우리가 만들던 킷을 버리고 팀원의 것을 쓴다. 그 앞에 특허를 모르는 사람용 안내 화면을 세운다.**

1.0 은 원고를 검사해 서류를 뽑는 데서 끝났다. 정작 「그래서 어디에 어떻게 내는가」 는
사람이 알아서 해야 했다. 2.0 은 그 뒤를 맡는다.

### 갈아탄 것 — 특허킷 2.7.0

회사공유 묶음으로 받은 팀원의 킷을 우리 1.0 과 견주었다. 모든 면에서 낫다.

| | 1.0 (우리 것) | 2.7.0 (팀원 것) |
| --- | --- | --- |
| 코드 | 1,602줄 · 2모듈 | **8,672줄 · 29모듈** |
| 명령 | 6개 | **23개** |
| 자체 시험 | 14개 | **131개** |
| 설치 | 파이썬을 미리 깔아야 함 | **설치.bat · 전용 파이썬 자리 · exe 묶음** |
| 없던 일 | — | 선행기술 조사 · 공개 증거 · 인용문헌 대비 · 구현 대조 · IR 포트폴리오 |

1.0 에 뒤늦게 더했던 **뒷받침 요건**과 **요약서 분량** 검사도 2.7.0 에 이미, 더 나은 꼴로
있었다(특허법 제42조제4항을 근거로 밝히고, 조사를 떼어 내며, 「있어서·포함하는」 같은
말을 걸러 낸다). 우리 것을 더 손보는 것은 같은 것을 두 번 만드는 일이라 그만두었다.

**2.7.0 이 우리가 못 보던 결함을 잡았다.** 도면 SVG 두 장이 XML 로 성하지 아니하였다.
`1.25 ≤ 기준값 < 2.0` 의 꺾쇠를 실체참조로 적지 아니한 것이다. 1.0 은 SVG 를 세기만 하고
한 번도 열어 본 적이 없었다. 고친 뒤 출원건_01 이 「가능」 으로 바뀌었다.

### 더한 것 — 출원 도우미 1.0

명세서가 다 된 뒤부터 관청에 내기까지를 맡는다. 브라우저 화면 일곱 마당이다.

| 마당 | 하는 일 |
| --- | --- |
| 0 | 원고 폴더를 고른다. 찾아보기 · 최근 목록 |
| 1 | 준비물 — 특허고객번호 · 전자문서 이용신고 · 인증서 |
| 2 | 원고 검사. 막는 값은 화면에서 바로 채운다 |
| 3 | 서류 만들기 — 제출본 · 도면 · DOCX · 준비서 |
| 4 | 비용 — 수수료를 셈한다 |
| 5 | 특허로에 내는 차례와 서식에 적을 값 |
| 6 | 낸 뒤 진행 상황 — 출원번호로 관청 기록을 부른다 |

**수수료 자동 계산.** 기본 46,000원(전자·국어) + 20면 초과 1면당 1,000원 − 감면(개인·중소
70%). 감면율은 설정의 글월에서 읽고, **못 읽으면 감면하지 아니한다** — 적게 잡는 편이 낫다.
실측 4건이 20,100 ~ 24,900원으로 저마다 달랐다.

**진행 상황 추적.** 출원번호를 넣으면 KIPRIS 서지상세를 불러 지금 상태(출원·공개·등록)를
보이고, 출원일에서 세어 세 기한을 셈한다. 공지예외 증명서류 30일(특허법 제30조제2항),
정식 명세서 1년(제42조의2제2항), 심사청구 3년(제59조제2항).

**어려운 말을 걷어냈다.** 「[오류] 미확정 — inventors[0].name 이 확정되지 않았다」 대신
「사람이 정해야 하는 값이 비어 있습니다」 라 하고 고칠 자리로 데려가는 단추를 붙였다.

### 자동화하지 못한 것과 그 까닭

「단추 한 번으로 출원까지」 는 **7번(인증서 서명 제출)에서 물리적으로 막힌다.**

특허청이 내놓은 API 는 KIPRIS·공공데이터포털의 **조회용뿐**이고 제출용 공개 API 가 없다.
제출은 명세서를 NK-Editor 로 `.HLZ` 로 바꾸고 특허로에서 **공동인증서로 서명**하는
법률행위다(특허법 제28조의3, 시행규칙 제9조의6). 팀원의 2.7.0 에도 이 기능은 없다.
만들 수 없어서다.

그래서 서명과 결제 두 칸만 사람에게 남기고 그 앞뒤를 모두 만든다.

### 정리한 것

폴더가 판별로 섞여 무엇을 쓰는 것인지 알기 어려웠다. 다섯 자리로 갈랐다.

```
원고/       일하는 곳 (extracted 는 뜻 없는 이름이라 바꿈)
도구/       지금 쓰는 것만. 폴더 이름에 판을 적는다
참고자료/   강사지침과 가이드
산출물/     뽑아낸 것. 날짜를 앞에 붙인다
보관/       지난 것. 지우지 아니한다
```

1.0 킷과 그 배포본은 `보관/구버전/` 으로 옮겼다. 지우지 아니한 것은 되짚을 일이 생겨서다.

### 화면을 다시 짠 것

ui-ux-pro-max 로 얼개를 잡았다. 짜임새는 Swiss/Minimalism 을 골랐으나 그것이 딸려 준
팔레트(테라코타)와 서체(Varela Round — 어린이 앱용)는 관공서 서류 도구에 맞지 아니하여
버리고 「Navy professional」 로 다시 찾았다. **남색은 관청, 초록은 됨, 붉은색은 막힘.**

- 진행 레일을 표제에 붙여 지금 몇째 마당인지 늘 보인다
- 마당마다 무엇을 하는 곳인지 한 줄로 적고, 끝에 다음 마당 단추를 둔다
- 고른 특허·낼 돈·마감을 늘 보이게 두되 본문을 가리지 아니한다
- 뜻이 색 하나에 걸리지 아니하도록 모든 상태에 아이콘과 글을 함께 둔다
- 이모지를 쓰지 아니하고 SVG 로 그린다

메인보드는 팀원 것이라 고쳐 쓰지 아니한다. 다만 두 창을 오가는 사람에게 딴 프로그램으로
보이면 헷갈리므로 **색 토큰만** 같은 값으로 맞춘다(`도구/메인보드_옷.py`).

### 고친 탈

| 탈 | 까닭 | 막은 법 |
| --- | --- | --- |
| 서류 만들기 결과가 표제에 겹쳐 그려짐 | 레일 단추가 `r${n}` 인데 결과 칸도 `r3` 이라 `getElementById` 가 헤더 것을 먼저 집음 | 레일을 `nav_${n}` 으로. 자체 점검에 id 겹침 검사 |
| 요약 띠가 본문 마지막 줄을 가림 | 붙박이 띠가 두 줄로 접혀 110px 을 먹음 | 넓은 창은 오른쪽 칸, 좁은 창은 접기 + 높이만큼 여백 |
| 배치 파일이 깨짐 (두 번) | `chcp 65001` 뒤의 한글을 cmd 가 잘못 쪼갬 | 배치를 ASCII 로만 두고 한글 경로는 `run.py` 가 풂 |
| 찾아보기가 한글 경로를 깨뜨림 | 자식 프로세스가 cp949 로 찍음 | `PYTHONIOENCODING=utf-8` 을 넘김 |
| API 경로 매칭 실패 | 한글 경로를 브라우저가 퍼센트 인코딩해 보냄 | 경로를 ASCII 로 |
| 문법 검사가 부실 | `ast.parse` 는 이름 풀이를 아니 함 | `compile()` 로 바꿈 |

### 실측

- 출원 도우미 자체 점검 통과 — 감면율 6가지 · 수수료 4가지 · 사전등록 2가지 ·
  화면 id 겹침 · 요약 여백 · 메인보드 길
- KIPRIS 실호출 — `1020240176792` 로 「공개 · 출원 2024-12-02 · 청구항 10항」 과 기한 3종
- 글자 대비 — 밝은 쪽 4.55~17.85:1, 어두운 쪽 5.51~14.27:1 (모두 WCAG AA 4.5:1 넘음)

### 넘어간 것

- **`.HLZ` 직접 만들기** — 형식이 공개되어 있지 아니하다. 짐작으로 만들면 관청이 받지
  아니하는 파일이 나온다. NK-Editor 를 거친다
- **메인보드 짜임새 손보기** — 팀원 것이다. 색만 맞추고 그친다. 2.8.0 이 나오면 옷을
  다시 입힌다(`--벗기기` 로 되돌릴 수 있다)
- **키워드 일일 모니터링** — 강사지침에 있으나 아직 아니 하였다

## 1.0.0 — 2026-08-26

**우리가 만든 첫 킷.** 명세서와 청구범위를 검사해 제출본과 관청 서식을 뽑는다.

- 검사 24항목 — 단락번호 연속성, 도면 인용 대조, 부호 대조, 청구항 인용 정합,
  명칭 3곳 일치, 카테고리 일원화, 문체·표기, 공지예외 기한
- 제출본 합치기 · DOCX · 출원서 기재사항
- 브라우저 화면(`gui.py`) · 배포용 묶음
- 강사지침의 가이드 두 편을 검사로 옮김 — 뒷받침 요건, 개방형 표현, 요약서 분량,
  하드웨어 결합
- 발명자 실명 검사 — 「홍길동」 같은 예시 이름을 막는다. 출원건_01 이 실제로 그 상태였다

**2.0.0 에서 갈음되었다.** `보관/구버전/특허자동화킷_1.0/` 에 있다.
