# 특허 자동화 킷

한국 특허청 임시명세서(가출원) 출원건을 **만들고 · 검증하고 · 제출본과 관청 서식을 뽑는** 도구다.
`myME_myIF_특허출원_20260821` 네 건의 작업 방식을 그대로 옮겨 담았으며, 그 네 건으로 실측 검증했다.

---

## 1. 설치

```bash
pip install python-docx
```

파이썬 3.10 이상이면 된다. `python-docx` 는 DOCX 생성에만, `playwright` 는 도면 PNG 렌더에만 필요하다.
검증과 제출본 생성은 표준 라이브러리만으로 돌아간다.

## 2. 쓰는 법

```bash
python patentkit.py init  출원건_05_새건 --제목 "…를 산출하는 지표 처리 장치, 그 방법 및 이를 기록한 컴퓨터 판독가능 기록매체"
python patentkit.py check 출원건_05_새건
python patentkit.py all   .
```

창 화면을 쓰려면 (특허를 모르는 사람용. 브라우저 창이 뜬다. 표준 라이브러리만 쓴다):

```bash
python gui.py
python gui.py --자가점검   # 창을 띄우지 아니하고 자료 추출만 확인한다
```

| 명령 | 하는 일 |
| --- | --- |
| `init` | 새 출원건 폴더와 뼈대 문서·설정을 만든다 |
| `check` | 검증만 한다. 파일을 고치지 아니한다 |
| `build` | `03_제출본_명세서_청구범위.md` 를 다시 만들고 검증한다 |
| `docx` | 검증 통과 시 `_출력/임시명세서_YYYYMMDD.docx` 와 `_출력/출원서_기재사항.md` 를 만든다 |
| `figures` | `도면/*.svg` 를 2배 해상도 PNG 로 렌더한다 |
| `all` | build + check + docx 를 한 번에 한다 |

대상 자리에 **상위 폴더**를 주면 `patent_config.json` 을 가진 하위 폴더를 모두 찾아 돈다.
종료 코드는 오류가 하나라도 있으면 `1`, 없으면 `0` 이다. CI 에 그대로 걸 수 있다.

## 3. 출원건 폴더의 구성

```
출원건_01_반증등급/
  patent_config.json            출원인·발명자·IPC·공지예외 등 서지사항
  01_명세서.md                  명세서 본문 (청구범위를 품고 있어도 된다)
  02_청구범위.md                청구범위 정본. 「## 회피 논거」 이하는 내부 검토용으로 제출본에서 빠진다
  03_제출본_명세서_청구범위.md   build 가 만든다. 직접 고치지 아니한다
  _발명의명칭.txt               명칭 대조용
  도면/                         도1_….svg / .png
  _출력/                        docx 가 만든다
```

**청구항의 정본은 `02_청구범위.md` 하나다.** 명세서가 청구범위를 품고 있으면 `build` 가 그 구간을
걷어내고 정본을 다시 끼운다. 제출본의 순서는 관청 표기 순서인 *명세서 본문 → 청구범위 → 요약서* 다.

### 가이드 근거

「가이드」 갈래는 `제작 참고자료/특허명세서작성 가이드라인.md` 가 따로 요구하는 것이다.

○ **뒷받침 요건** (6.1) — 청구항에만 있고 발명의 설명에 없는 구성요소는 거절이유다.
  청구항에서 「~부·모듈·유닛·엔진」 으로 끝나는 낱말을 뽑아 조사를 떼고 명세서와 대조한다.
  「내부·일부」 같은 보통말은 세지 아니한다.

○ **확정적 표현** (1.3) — 개방형 표현이 원칙이다. 확정적 기재는 권리범위를 좁힌다.

○ **요약서 분량** (7.1) — 가이드 권장은 200자 내외다. 400자를 넘으면 알린다.

○ **하드웨어 결합** (5.1) — AI·SW 발명은 하드웨어와 묶어 적는다.

### 종전 킷의 오탐을 고친 곳

단락번호 연속성 검사는 **행 머리의 `[XXXX]` 표지만** 센다. 본문에 인용된 단락 참조(「[0058]의 …」)를
표지로 세면 참조 하나가 앞뒤 두 곳의 불연속으로 계수되어 없는 결번이 보고된다.

같은 이유로 도면 인용은 앞에 한글이 붙지 않은 `도 N` 만, 부호는 괄호 안 세 자리 이하 숫자만 센다.
「산소포화도 16」 이나 「Standards of Care(2025)」 를 도면·부호로 세지 아니한다.

## 5. 사람이 채워야 하는 값

`patent_config.json` 의 `★` 표식은 킷이 **풀 수 없는 차단 사유**다. 값을 채우기 전에는 관청 서식 생성이
막힌다. 보통 다음 두 값이다.

| 값 | 자리 | 형식 |
| --- | --- | --- |
| 발명자 성명 | `inventors[0].name` | 한글·한자 2~6자 또는 영문 성명 |
| 사업자등록번호 | `applicants[0].biz_no` | `000-00-00000` |

발명자 확정 시 퇴사자와 사외 공동발명자를 누락하지 아니한다. 명목상 등재와 공동발명자 누락은
모두 무효사유에 해당한다.

## 6. 킷이 하지 아니하는 일

○ **선행기술 조사와 저촉 판단을 하지 아니한다.** KIPRIS 조회·확대선원 대비는 사람이 한다.

○ **청구범위의 권리범위 설계를 하지 아니한다.** 문언의 형식 정합만 본다.

○ **관청 전자출원(KIPOnet) 제출을 하지 아니한다.** `_출력/출원서_기재사항.md` 는 서식에 옮겨 적는 자료다.

○ **공지예외 증명서류를 만들지 아니한다.** 출원일부터 30일 이내 제출 기한만 알린다(특허법 제30조제2항).

## 7. 자체 점검

```bash
python test_patentkit.py
```
