# 특허 자동화 킷 (patentkit)

명세서와 청구범위를 마크다운으로 쓰고, 제출본 합치기·형식 검사·관청 서식 생성을
명령 한 줄로 처리하는 도구다. 퍼스널에이아이 특허 출원 작업에서 손으로 하던 확인을
자동화한 것으로, 사람이 판단해야 하는 값(발명자·사업자등록번호 등)이 비어 있으면
서식 생성을 막는다.

**명세서를 쓰는 일**

- **검사(validate)** — 관청 표제 누락, 단락번호 결번·중복·역행, 청구항 인용 정합,
  카테고리 일원화, 도면·부호 정합, 문체 위반, 제출본 불일치, 기한을 한 번에 본다.
- **제출본(build)** — 명세서 + 청구범위 + 요약서를 관청 표기 순서로 합친다.
- **번호(renumber)** — 단락을 넣고 뺀 뒤 어긋난 [0001] 번호를 다시 매기고,
  본문 안의 단락 인용도 함께 고친다.

**관청에 낼 것을 만드는 일**

- **서식(docx)** — 제출용 DOCX 를 만든다.
- **도면(figures)** — 도면 SVG 를 제출용 PNG 로 렌더한다. 엣지·크롬을 쓰므로 추가 설치가 없다.

**조사하고 뒷받침하는 일**

- **선행기술(prior-art)** — KIPRIS 결과를 읽어 자사 선출원·확대된 선원 후보·공개
  선행문헌으로 갈라 놓고, 먼저 읽을 문헌의 차례를 매긴다.
- **공개 증거(evidence)** — 출원 전에 공개돼 있던 자원을 응답 헤더째 받아 둔다.
  공지예외(특허법 제30조) 증명 자료가 된다.
- **인용문헌 대비(compare)** — 우리 독립항을 구성요소로 쪼개 상대 청구항과 나란히 놓고,
  확대된 선원은 명세서 전문과 용어를 대조한다.
- **구현 대조(trace)** — 청구항 구성이 제품 소스의 어느 파일 몇 행에 있는지 대조하고,
  그 뒤 소스가 바뀌면 알려 준다.

**여러 건을 살피는 일**

- **현황(status)** — 여러 출원건의 상태를 한 표로 본다.
- **검토 초안(report)** — 위의 결과를 모아 변리사에게 넘길 초안과 종합보고서를 만든다.

## 1. 회사에 배포하기

받는 사람은 **파이썬을 몰라도 되고 미리 깔 필요도 없다.** 압축 파일 하나를 보내면 된다.

### 배포본 만들기 (보내는 쪽)

```bash
python 배포만들기.py
```

`배포/특허킷_2.7.0.zip` (약 4.5MB)과 `배포/특허킷_exe_2.7.0.zip` (약 14MB)이 만들어진다.
앞의 것을 메일이나 사내 드라이브로 보낸다. 안에는 설치.bat · 제거.bat · 사용안내.md ·
킷과 딸린 꾸러미(wheel)가 들어 있다.

### 설치하기 (받는 쪽)

1. 압축을 푼다.
2. **설치.bat** 을 두 번 누른다.
3. 파이썬이 없으면 설치할지 물어본다. **Y** 를 누르면 winget 으로 알아서 깔린다.
4. 바탕화면에 아이콘 셋이 생긴다.

| 아이콘 | 하는 일 |
| --- | --- |
| **특허 자동화 킷 메인보드** | 브라우저가 열리고 거기서 전부 처리한다. **대부분 이것만 쓰면 된다.** |
| 특허 자동화 킷 메인보드 (사내망 공유) | 같은 사내망의 다른 PC 에서도 열린다. 시연용 |
| 특허 자동화 킷 | 번호로 고르는 화면. 창 없이 쓸 때 |

출원건 폴더는 **아이콘을 누른 폴더 → 위 폴더 → 바탕화면 → 문서** 차례로 알아서 찾는다.
못 찾으면 어디를 찾아봤는지 보여 준다.

관리자 권한이 필요 없다. 설치되는 곳은 `%LOCALAPPDATA%\Programs\PatentKit\` 한 곳뿐이며,
전용 파이썬 자리(venv)를 따로 만들므로 그 PC 의 다른 파이썬 환경을 건드리지 않는다.
인터넷이 없어도 설치된다. 꾸러미를 배포본 안에 넣어 두었다.

설치가 끝나면 자체 시험 131가지를 자동으로 돌려 「통과 131 · 실패 0」을 확인한 뒤 마친다.

### 제거

**제거.bat** 을 두 번 누른다. 바탕화면 아이콘 · 시작 메뉴 · PATH · 프로그램 파일이 모두
원래대로 돌아간다. **출원건 자료에는 손대지 않는다.**

### exe 배포본도 함께 만든다

`배포만들기.py` 는 두 벌을 만든다.

| 배포본 | 무엇 | 언제 |
| --- | --- | --- |
| `특허킷_2.7.0.zip` (약 4.5MB) | 설치본. 설치.bat 이 파이썬을 잡고 전용 venv 에 넣는다 | **회사 배포에는 이쪽** |
| `특허킷_exe_2.7.0.zip` (약 14MB) | 실행 파일 하나. 파이썬이 없어도 두 번 누르면 돈다 | 파이썬을 깔 수 없는 PC · USB |

### exe 를 정식으로 배포하려면 무엇이 필요한가

구운 exe 에는 **코드 서명이 없다.** 서명이 없으면 두 가지가 걸린다.

- **SmartScreen** — 「Windows의 PC 보호」 창이 뜬다. 「추가 정보 → 실행」으로 열 수 있다.
- **Smart App Control** — 윈도우 11 에서 켜져 있으면 실행 자체가 막힐 수 있다.

> 서비스가 안전하다고 판단하지 못하면 서명을 본다. 서명이 없거나 유효하지 아니하면
> 신뢰할 수 없는 것으로 보고 차단한다. Microsoft Trusted Root Program 에 속한
> 인증기관이 발급한 인증서로 서명돼 있으면 실행을 허용한다.
> — [Microsoft, Smart App Control FAQ](https://support.microsoft.com/en-us/windows/security/threat-malware-protection/smart-app-control-frequently-asked-questions)

따라서 필요한 것은 **신뢰된 인증기관의 코드 서명 인증서** 하나다.

| 방법 | 드는 것 | 효과 |
| --- | --- | --- |
| Microsoft Artifact Signing (옛 Trusted Signing) | 월 9.99 달러부터 · 신원 검증 | Smart App Control 통과 |
| CA 의 OV 인증서 | 기관마다 다름 · 신원 검증 | 위와 같다 |
| CA 의 EV 인증서 | 더 비쌈 | **SmartScreen 우회 효과는 없어졌다** |
| 자체 서명 | 무료 | **권하지 아니한다.** 아래 실측 참조 |

> EV 인증서는 더 이상 SmartScreen 을 건너뛰지 못한다. 몇 해 전에는 EV 로 서명하면
> 기본적으로 좋은 평판을 받았으나 그 동작은 없어졌다.
> — [Microsoft Learn, SmartScreen reputation](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation)

**이 PC 에서 실제로 재어 본 결과(2026-08-25, Smart App Control 켜짐)**

| 상태 | 결과 |
| --- | --- |
| 서명 없는 exe | 실행됐다 |
| 같은 exe 를 자체 서명 | **차단됐다** — An Application Control policy has blocked this file |

같은 파일이라도 PC 와 때에 따라 결과가 달라진다. 판단이 클라우드 평판에 달려 있기
때문이다. **회사 전체에 뿌릴 때에는 설치본을 쓰는 편이 확실하다.**

인증서를 마련한 뒤에는 exe 배포본 안의 `서명하기.ps1` 한 줄로 서명한다.

## 2. 개발자용 설치

소스를 직접 고칠 사람만 보면 된다.

```bash
python -m patentkit doctor      # 환경과 기능별 준비 상태
python -m patentkit selftest    # 자체 시험 131가지
python -m patentkit install     # 이 컴퓨터에 설치(바탕화면 아이콘·PATH)
```

검사·제출본·단락번호·선행기술 조사·공개 증거·구현 대조는 표준 라이브러리만으로 돈다.
나머지 둘은 다음과 같다.

| 기능 | 필요한 것 |
| --- | --- |
| 관청 서식(DOCX) | `pip install python-docx` |
| 도면 SVG → PNG | 마이크로소프트 엣지나 크롬이 깔려 있으면 **추가 설치 없이** 된다. 없으면 `pip install playwright` 뒤 `playwright install chromium`, 또는 `pip install cairosvg` |
| 인용문헌 PDF 읽기 | `pip install pypdf` (배포본에 함께 들어 있다). txt 로 저장해 두면 없어도 된다 |

### 명령줄이 익숙하지 않다면

설치 후 바탕화면 아이콘을 누르거나, 소스 폴더의 **`특허킷.bat`** 을 두 번 누른다.
번호로 고르는 화면이 뜬다.

```
   1. 웹 메인보드 열기            10. 선행기술 조사 결과 보기
   2. 출원건 현황 한눈에 보기     11. 인용문헌 대비표 만들기
   3. 새 출원건 폴더 만들기       12. 공개 증거 받아 두기
   4. 검사하기                    13. 청구항·제품 소스 대조
   5. 제출본 만들기               14. 변리사 검토 초안·종합보고서
   6. 도면 초안 만들기 (SVG)      15. 발명 후보 원장
   7. 도면 그리기 (SVG → PNG)     16. IR 포트폴리오·등록성 분석
   8. 관청 서식(DOCX) 만들기      17. 실행 환경 점검
   9. 단락번호 다시 매기기        18. 이 컴퓨터에 설치 · 0. 나가기
```

**1번이 기본 길이다.** 브라우저가 열리고, 아래 「웹 메인보드」에서 하는 모든 일을
그 화면에서 누르기만 하면 된다. 나머지 번호는 창 없이 쓸 때를 위한 것이다.

출원건 폴더는 현재 폴더 → 위 폴더 → 바탕화면 → 문서 차례로 자동으로 찾는다.
못 찾으면 어디를 찾아봤는지 보여 주고 폴더를 물어본다. 그때는 탐색기에서 폴더를
창으로 끌어다 놓고 Enter 를 누른다.

설치한 뒤에는 아무 창에서나 `특허킷 validate 출원건_01` 처럼 쓸 수 있다.

## 3. 웹 메인보드 — 브라우저에서 전체를 다룬다

```bash
python -m patentkit web
```

바탕화면 아이콘을 눌러 **1번**을 골라도 같다. 기본 브라우저가 열리고 그 화면에서
검사부터 관청 서식 생성까지 전부 처리한다. 명령을 하나도 외우지 않아도 된다.

**어디까지 열리나** — `127.0.0.1` 에만 붙고, 띄울 때마다 새 열쇠를 만들어 주소에
붙인다. 열쇠 없는 요청은 403 이다. 사내망이든 사외망이든 다른 PC 에서는 열리지
않는다. 창을 닫으면 화면도 닫힌다. 파일은 프로젝트 폴더 안, 정해진 확장자만 내준다.

### 화면 구성

왼쪽에 출원건 목록이 서고, 각 건마다 **오류 수·준비 눈금**이 함께 보인다.
건을 누르면 오른쪽에 그 건의 준비 단계가 동그란 눈금으로 늘어서고, 그 아래 아홉 개
탭에 **실제 자료가 표로** 나온다. 무엇을 눌러야 하는지는 「다음에 할 일」이 알려 준다.

| 탭 | 화면에 나오는 실제 자료 |
| --- | --- |
| 한눈에 | 명칭·청구항·단락·도면 수, 공지예외/우선일 남은 날, 만들어 둔 문서 목록 |
| 검사 | 지적 하나하나를 등급·항목·규칙·파일·행까지 표로 |
| 선행기술 | KIPRIS 문헌 전건. 겹침·판정·출원번호(누르면 KIPRIS)·출원인·출원일·공개일·겹친 낱말 |
| 대비 | 대비할 문헌 목록과 확보 상태, 구성요소별 청구항 대비표, 확대선원 전문 용어 대조표 |
| 구현 | 청구항 구성요소마다 소스 파일·행과 지문 판정(구현 확인·바뀜·행 벗어남) |
| 도면 | 만들어진 PNG 를 격자로. 누르면 크게 본다 |
| 증거 | 받아 둔 공개 증거의 확인 시각·주소·응답·접근 통제·크기·제목 |
| 설정 | `patent_config.json` 을 **화면에서 고친다.** ★ 미확정 칸은 붉게 표시된다 |
| 산출물 | 제출본·조사 결과·대비표·검토 초안을 그 자리에서 열어 읽는다 |

빈 탭은 비워 두지 않는다. 무엇이 없어서 비었는지와, 채우려면 어느 단추를 눌러야
하는지를 그 자리에 적는다.

### 화면에서만 되는 일

- **설정 고치기** — 발명자·사업자등록번호 같은 ★ 값을 폼에 넣고 「설정 저장」을
  누르면 파일에 바로 쓰고 다시 검사한다. 오류 2 → 오류 0 → **출원 가능**이 한 화면에서
  끝난다. 고칠 수 있는 칸은 허용 목록에 있는 것뿐이고, 그 밖의 값은 파일을 직접 고친다.
- **발명 후보 원장** — 「출원건에서 채우기」를 누르면 이미 있는 출원건이 그대로
  후보로 올라온다. 킷은 청구항 수·검사 오류·선행문헌·자사 저촉·청구항 전문 확보·구현
  확인을 세어 보이고, **등급은 사람이 고른다.** 고른 등급은 판단자와 날짜와 함께 남는다.
- **근거와 출처** — 킷이 보고서에 적는 법령 문구를 원문 출처와 함께 늘어놓는다.

### 다른 PC 에서도 열기 (시연·공유)

기본은 이 PC 에서만 열린다. 시연이나 공유가 필요하면 사내망에 연다.

```bash
python -m patentkit web --host lan
```

띄우면 두 주소가 함께 나온다. 다른 PC 에는 위의 사내망 주소를 알려 준다.

```
  주소 — http://10.10.10.72:8830/?key=DllVbkMw5_aA4MpoHsqchvDb6X6tGYG0
  이 PC 에서 — http://127.0.0.1:8830/?key=DllVbkMw5_aA4MpoHsqchvDb6X6tGYG0
```

- 열쇠는 그대로 필요하다. 열쇠 없는 요청은 **403** 이다.
- **주소에 붙은 열쇠를 아는 사람은 출원 자료를 읽고 작업을 실행할 수 있다.**
  메신저 단체방에 올리지 않는다. 열쇠는 창을 닫으면 사라진다.
- 다른 PC 가 처음 열면 화면 위에 「사내망 공개 중 · 다른 PC N대」 가 뜨고,
  **실행 기록**에 그 주소가 남는다. 누가 보고 있는지 화면에서 보인다.
- 사내망 밖(인터넷)에는 열리지 않는다. 그러려면 방화벽·공유기를 따로 손봐야 하는데,
  출원 전 자료를 인터넷에 여는 일은 권하지 않는다.
- 주소를 직접 지정해도 된다. `--host 192.168.0.10`

시연이 끝나면 서버 창을 닫는다. `--host` 를 빼면 다시 이 PC 전용이다.

### 단축키

`R` 새로고침 · `1`~`9` 탭 이동 · `Esc` 목록으로 · 주소 끝의 `#case=…&tab=…` 은
그대로 즐겨찾기에 넣어도 된다.

## 4. 5분 사용법

```bash
python -m patentkit init 출원건_05_새발명 --title "값을 산출하는 값 처리 장치, 그 방법 및 이를 기록한 컴퓨터 판독 가능 기록매체"
```

만들어진 폴더에서 다음 순서로 일한다.

1. `patent_config.json` 의 ★ 값을 채운다 (발명자·사업자등록번호·특허고객번호).
2. `01_명세서.md` 와 `02_청구범위.md` 의 ★ 자리를 채운다.
3. 검사한다. `python -m patentkit validate 출원건_05_새발명`
4. 제출본을 만든다. `python -m patentkit build 출원건_05_새발명`
5. 서식을 만든다. `python -m patentkit docx 출원건_05_새발명 --cover`

여러 건을 한꺼번에 볼 때는 출원건들을 담고 있는 상위 폴더를 준다.

```bash
python -m patentkit status . --out 09_출원준비_최종점검.md
```

## 5. 폴더와 파일 규칙

```
출원건_05_새발명/
  01_명세서.md                     ← 명세서 정본
  02_청구범위.md                   ← 청구범위 정본 (말미의 「회피 논거」는 내부용)
  03_제출본_명세서_청구범위.md      ← build 가 만든다. 손으로 고치지 않는다
  04_변리사_검토사항.md
  patent_config.json               ← 출원인·발명자·기한·서식 설정
  도면/                            ← 도1_*.svg → 도1_*.png
  _근거자료/                       ← 실측 스크립트와 측정 결과
  _작업이력/                       ← 백업과 단락번호 대응표가 쌓인다
  _출력/                           ← DOCX 가 나온다
```

마크다운 표기 규칙은 다음과 같다. 검사는 이 규칙을 전제로 한다.

- 관청 표제는 `## 【명세서】`, `### 【기술분야】` 처럼 표제 안에 `【 】` 로 적는다.
- 단락 표지는 **행 머리**에 `[0001] ` 로 적는다. 행 가운데의 `[0058]` 은 다른 단락을
  가리키는 인용으로 보고 표지로 세지 않는다.
- 청구범위와 요약서에는 단락 표지를 붙이지 않는다.
- 청구항 표제는 `### 【청구항 1】` 로 적고, 각 항은 `…, 값 처리 장치.` 처럼 범주 명사로 끝낸다.

### 이 킷이 하지 않는 것

- 신규성·진보성 판단과 청구범위의 넓고 좁음에 대한 판단은 하지 않는다.
  선행기술은 **찾아서 갈라 놓기까지**만 하고, 대비와 판단은 사람이 한다.
- 발명자 확정, 승계 절차, 공동출원 여부는 사람이 정한다. 킷은 값이 비었다는 사실만 막는다.
- 검사를 통과했다는 것은 형식 결함이 없다는 뜻이며, 변리사 검토를 대신하지 않는다.

## 8. 조사하고 뒷받침하기

### 선행기술 — `prior-art`

KIPRIS 에서 받은 결과 JSON 을 `_원본자료` 폴더에 두고 실행한다. 출원건 옆과
프로젝트 전체의 `_원본자료` 를 함께 읽는다.

```bash
python -m patentkit prior-art 출원건_04_결측구간 --date 2026-08-25
```

건마다 셋 중 하나로 가른다. **날짜와 출원인 이름만으로 정해지는 사실 판정**이며
신규성·진보성 판단이 아니다.

| 판정 | 뜻 | 해야 할 일 |
| --- | --- | --- |
| 자사 선출원 | 출원인이 우리 회사 | 겹치는 한정을 독립항에서 뺀다 |
| 확대된 선원 후보 | 우리 출원일 전에 출원됐고 그때까지 미공개(제29조제3항) | **명세서 전문**을 확보해 대비 |
| 공개 선행문헌 | 우리 출원일 전에 공개됨(제29조제1항) | 청구항 전문을 확보해 대비 |

「겹침」은 우리 명칭·독립항의 낱말이 문헌 명칭·초록에 몇 개나 나오는지 센 값으로,
먼저 읽을 문헌의 차례를 정하는 데에만 쓴다. 범주 명사(장치·방법·기록매체)는 세지 않는다.

`patent_config.json` 의 `prior_art.kipris_key` 를 채우면 `--fetch` 로 직접 조회해
결과를 저장한다. 열쇠가 없어도 저장된 결과만으로 보고서가 만들어진다.

### 공개 증거 — `evidence`

```bash
python -m patentkit evidence 출원건_04_결측구간 https://example.com https://example.com/console
```

주소마다 본문(`*.html`)과 **응답 헤더 전문**(`*_headers.txt`), 내려받은 시각(KST)을
남기고 `공개이력대장.md` 를 만든다. 401·403 이 오는 경로도 그대로 적는다.
「인증이 필요했다」는 사실이 공개되지 아니하였다는 증거가 되기 때문이다.

○ 화면 캡처만으로는 게시일이 특정되지 않는다. 배포 이력·저장소 커밋·업로드 기록을 함께 모은다.
○ 공지예외를 주장하면 증명서류를 **출원일부터 30일 안**에 내야 한다(제30조제2항).

### 인용문헌 대비 — `compare`

`_근거자료/대비문헌.json` 에 대비할 문헌을 적는다. 상대 청구항 전문은 그대로 붙여도 되고,
파일 이름을 적어도 된다. 확대된 선원은 명세서 전문 파일(txt 또는 **pdf**)을 적는다.

```bash
python -m patentkit compare 출원건_04 --init   # 문헌 목록 뼈대
python -m patentkit compare 출원건_04          # 대비표 두 벌을 만든다
```

**청구항 대비(07)** — 우리 독립항을 구성요소로 쪼개고(전제부·각 구성부·말미 한정),
상대 청구항에서 낱말이 가장 많이 겹치는 문언을 찾아 나란히 놓는다. 대응 문언을 찾지
못한 축은 회피 논거를 쓸 자리이므로 따로 모아 초안으로 싣는다.

**전문 용어 대조(08)** — 확대된 선원은 청구항이 아니라 명세서 전문과 대비한다
(제29조제3항). 대조 용어가 각 문헌 전문에 몇 번 나오는지 세고, 나온 자리의 문장을
근거로 함께 싣는다. 용어는 `patent_config.json` 의 `compare.terms` 로 정하며,
비워 두면 독립항의 구성부 이름에서 뽑는다. 이형태는 `"E-value · E값"` 처럼 묶어 적는다.

**두 가지를 반드시 알고 써야 한다.**

- 「대비」 칸은 비워 둔다. 문언이 실제로 대응하는지, 회피가 되는지는 사람이 판정한다.
- 우리 청구항이 한글이고 상대가 영문이면 **낱말로 대조할 수 없다.** 킷은 그 경우
  「대응 없음」이라고 적지 않고 「언어가 달라 대조하지 못했다」로 표시한다.
  이 문헌은 사람이 직접 읽고 대비해야 한다.

### 상대 청구항을 KIPRIS 에서 받아 온다

대비표의 「상대 청구항」 칸은 손으로 옮겨 적던 자리다. 옮겨 적다 한 줄을 빠뜨리면
회피 논거가 사실과 어긋나므로, 받아 올 수 있으면 받아 온다.

```bash
python -m patentkit compare 출원건_01 --fetch-claims
```

메인보드에서는 **대비** 탭의 「KIPRIS 에서 상대 청구항 받아오기」 단추다.

- 쓰는 곳 — KIPRIS Plus REST `getBibliographyDetailInfoSearch` (출원번호로 서지와 청구항).
  터는 `https://plus.kipris.or.kr/kipo-api/kipi/patUtiModInfoSearchSevice/` 다.
- **열쇠가 있어야 돈다.** [KIPRIS Plus](https://plus.kipris.or.kr) 나 공공데이터포털에서
  발급받아 `patent_config.json` 의 `prior_art.kipris_key` 에 넣거나 환경변수
  `KIPRIS_KEY` 로 준다. 메인보드 **설정** 탭에서 넣어도 된다 — 넣은 열쇠는 파일에만
  남고 화면으로 되돌려 보내지 않는다.
- 채운 글이 **어디서 언제 왔는지 함께 남는다**(`청구항출처`·`청구항받은때`). 사람이
  옮겨 적은 글과 기계가 받아 온 글은 뒤에 다투는 자리가 다르기 때문이다. 받은 응답
  원본은 `_근거자료/KIPRIS원본/*.xml` 에 그대로 둔다.
- 이미 채워진 문헌은 다시 받지 않는다. 다시 받으려면 `--refetch`.
- 출원번호가 아닌 문헌(예: `US 11,908,581 B2`)은 물어보지 않고 건너뛴다. 한국 특허청
  API 이므로 외국 문헌은 사람이 넣는다.
- 응답에 청구항이 없으면 **없다고 말한다.** 지어내지 않는다.

> 응답의 칸 이름은 서비스 개정에 따라 달라져 왔다(`claimInfoArray/claimInfo/claim`,
> `patentClaimInfo` 등). 그래서 이름을 못박지 않고 이름에 `claim` 이 들어간 칸을 나온
> 차례대로 훑는다. 청구항 「수」를 담는 칸은 글이 아니므로 뺀다.

#### KIPRIS 열쇠 받는 법

킷 안에도 넣어 두었다. 아무 창에서나 `patentkit kipris` 를 치면 아래 내용을 그대로
보여 주고, 열쇠가 있으면 **실제로 도는지 한 번 물어봐서 확인**해 준다.

길이 둘이다. 어느 쪽 열쇠든 이 킷에 그대로 넣으면 된다.

**가. KIPRIS Plus** — 특허청 정보원이 직접 내주는 열쇠

1. [plus.kipris.or.kr](https://plus.kipris.or.kr) 에서 회원 가입한다.
   법인 계좌나 법인 카드로 결제하려면 **단체회원**으로 가입한다.
2. 위 메뉴의 **Open API** 에서 「특허·실용 공개·등록 공보」를 고른다.
   청구항은 이 서비스의 `getBibliographyDetailInfoSearch` 에 들어 있다.
3. 장바구니에서 이용 조건과 할인 유형을 적어 신청한다.
   **관리자 승인이 나야 결제 단추가 열린다.** 마이페이지에서 확인한다.
4. 마이페이지에서 견적서를 뽑아 계좌이체나 신용카드로 낸다.
5. **마이페이지 > APIKEY 관리**에서 인증키를 확인한다. 그것이 열쇠다.

값 — 달마다 **1,000회까지 무료**이고 매월 1일에 다시 채워진다. 넘겨 쓰면 하루
5,320원(연 1,941,800원)이다. 상품을 둘 이하로 신청하면 50%, 개인·중소중견기업·
공공기관·비영리 단체는 여기에 50% 를 더 깎는다.
문의 — 02-6915-1553 (평일 09:00~12:00, 13:00~18:00)

**나. 공공데이터포털** — 같은 자료를 무료로 여는 길

1. [data.go.kr](https://www.data.go.kr) 에서 회원 가입한다.
2. 「특허실용신안 정보 검색 서비스」를 찾아 **활용신청**을 누른다.
3. **개발계정은 자동승인**이라 신청과 동시에 열린다.
   마이페이지 > 오픈API > 개발계정에서 일반 인증키를 복사한다.
4. 하루 1,000건까지 쓸 수 있다. 더 필요하면 운영계정으로 바꾼다.

> **함정 하나.** 포털 열쇠는 Encoding·Decoding 두 벌로 나온다. 이 킷은 값을 스스로
> 감싸므로 **Decoding 열쇠**를 넣는다. Encoding 열쇠를 넣으면 `%2B` 가 두 번 감싸져
> 인증이 되지 않는다.

**넣는 곳** — 메인보드 **설정** 탭의 「KIPRIS 서비스 열쇠」 칸(권함), 또는
`patent_config.json` 의 `prior_art.kipris_key`, 또는 환경변수 `KIPRIS_KEY`.
넣은 열쇠는 파일에만 남고 화면으로 되돌려 보내지 않으며, 칸을 비운 채 저장해도
지워지지 않는다.

**넣은 뒤 확인**

```bash
patentkit kipris
```

실패하면 오류 문구를 사람 말로 풀어 준다 — 열쇠 미등록·한도 초과·기한 만료·망 차단을
각각 다르게 안내한다.

**한도를 아끼는 장치** — 받은 응답 원본을 `_근거자료/KIPRIS원본/*.xml` 에 남기고,
같은 문헌을 다시 요청하면 **부르지 않고 그 파일을 읽는다.** 정말 다시 받아야 할 때만
`--refetch` 를 준다.


### 구현 대조 — `trace`

명세서에 적은 구성이 제품에 실제로 있는지 파일·행 단위로 확인한다.

```bash
python -m patentkit trace 출원건_04 --init                    # 대조표 뼈대
python -m patentkit trace 출원건_04 --source ../제품 --update  # 확인하고 지문 남기기
python -m patentkit trace 출원건_04 --source ../제품           # 그 뒤로는 이것만
```

`_근거자료/구현대조.json` 에 청구항별로 소스 파일과 행 범위를 적으면, 킷이 그 행의
내용을 줄여 **지문**으로 남긴다. 나중에 소스가 바뀌면 「소스 바뀜」으로 잡히므로
「그때는 맞았으나 지금은 다르다」를 가려낼 수 있다.

| 판정 | 뜻 |
| --- | --- |
| 구현 확인 | 그 행의 내용이 확인 당시와 같다 |
| 소스 바뀜 | 내용이 달라졌다. 구성이 그대로인지 다시 보고 `--update` |
| 행 범위 벗어남 | 파일이 짧아졌다 |
| 파일 없음 | 경로가 바뀌었거나 지워졌다 |
| 지문 없음 | 아직 확인하지 않았다 |

## 9. 규칙 바꾸기

출원건마다 `patent_config.json` 의 `validation` 으로 조절한다.

```json
"validation": {
  "strict": true,
  "style_checks": true,
  "min_claims": 1,
  "forbidden_in_independent_claims": ["온디바이스", "사용자 단말 내에서"],
  "required_sections": ["명세서", "발명의 명칭", "기술분야", "…"],
  "recommended_sections": ["선행기술문헌", "부호의 설명", "대표도"]
}
```

- `forbidden_in_independent_claims` — 독립항에 들어가면 안 되는 어구를 적는다.
  자사 선출원과 저촉되는 한정을 막는 데 쓴다.
- `style_checks` 를 `false` 로 두면 문체 검사를 건너뛴다.
- `build.internal_sections` 에 적은 절은 제출본에서 빠진다. 기본값은 `["회피 논거"]` 다.

서식은 `style` 로 조절한다. `font_kr`, `heading_sizes`, `body_size`, `table_style`,
`template_docx`(회사 서식 파일 경로)를 쓴다.

## 10. 자주 나오는 상황

**「제출본 불일치」가 뜬다** — 명세서나 청구범위를 고친 뒤 `build` 를 돌리지 않았다.
`python -m patentkit build 폴더` 를 실행한다.

**「미확정」오류로 DOCX 가 안 만들어진다** — `patent_config.json` 에 ★ 가 남아 있다.
관청 서식에 그대로 인쇄되는 값이므로 채우고 다시 돌린다. 검토용 초안이 필요하면
`--force` 를 준다.

**단락번호가 어긋났다** — `renumber --dry-run` 으로 무엇이 바뀌는지 먼저 보고,
그다음 `renumber` 를 돌린다. 원본은 `_작업이력` 에 백업되고 대응표가 함께 남는다.
같은 번호가 두 번 있으면 그 번호를 가리키는 본문 인용은 손대지 않고 알려 준다.

**도면 렌더가 안 된다** — `doctor` 의 「도면 SVG → PNG」 줄을 본다. 엣지나 크롬이 있으면
그대로 되고, 없을 때만 playwright 나 cairosvg 를 깐다.

**설치.bat 이 파이썬을 못 찾는다** — winget 이 막혀 있는 PC 다.
<https://www.python.org/downloads/> 에서 3.12 를 사용자 범위로 설치한 뒤 설치.bat 을 다시 누른다.

**바탕화면 아이콘을 눌러도 창이 곧바로 닫힌다** — `%LOCALAPPDATA%\Programs\PatentKit\특허킷.cmd`
를 직접 실행해 무슨 메시지가 나오는지 본다. 대개 설치가 반쯤 끝난 경우이며,
제거.bat 을 돌린 뒤 다시 설치하면 된다.

**소스 폴더에서 `특허킷.bat` 을 눌러도 아무 일이 없다** — 폴더에 이름이 비슷한 것이 둘 있다.
파이썬 꾸러미 폴더 `patentkit\` 과 실행 파일 `특허킷.bat` 이며, 눌러야 하는 것은 뒤쪽이다.

**콘솔에서 한글이 깨진다** — 윈도우 명령 프롬프트에서 `chcp 65001` 을 먼저 실행하거나
Windows Terminal 을 쓴다.

## 11. 만든 것을 확인한 방법

이 킷은 이미 완성돼 있던 출원건 4건(반증등급·인과게이트·기준출처·결측구간)에 그대로
돌려 확인했다.

- 네 건 모두 제출본을 다시 만든 결과가 기존 파일과 **글자 단위로 같다**(「제출본 변동 없음」).
- 단락 수·청구항 수·독립항 번호·도면 수가 기존 점검 문서의 수치와 일치한다.
- 검사 결과 남는 오류는 사람이 확정해야 하는 값 2칸(사업자등록번호·발명자 성명)뿐이다.
- 도면 4매를 SVG 에서 PNG 로 다시 렌더해 한글 글꼴과 부호 표기를 눈으로 확인했다.
- 선행기술 판정을 실제 KIPRIS 결과 97건으로 돌려 자사 선출원 10건이 가려지는 것을 확인했다.
- 킷이 보고서에 적는 법령 문구는 모두 1차 출처에서 확인했다. `patentkit sources` 로 볼 수 있다.
- 07·08 대비표를 실제 인용문헌(영문 등록특허 청구항 2건, 국내 공개공보 전문 5건)으로 만들어,
  구성부 이름이 축으로 잡히는 것과 언어가 다른 문헌이 「대조 못 함」으로 갈리는 것을 확인했다.
- `selftest` 는 결함을 심어 검사가 잡아내는지 131가지로 확인한다. `pytest tests/` 로도 돈다.

배포 절차도 실제로 돌려 확인했다. 배포본을 만들고, 압축을 풀고, 설치.bat 으로 설치해
바탕화면 아이콘·시작 메뉴·PATH 가 잡히는 것과 설치본에서 자체 시험이 모두 통과하는 것,
제거.bat 으로 그 셋이 모두 원래대로 돌아가는 것까지 확인했다.
